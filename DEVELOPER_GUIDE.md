# Гід розробника — з чого і в якому порядку складається ця гра

Практичний покроковий довідник: де що лежить, що від чого залежить, і в
якому порядку робити зміни, щоб нічого не зламати. Не дублює цифри
(`PROGRESSION_ECONOMY.md`) чи опис механік (`GAME_DESIGN.md`) — тут лише
АРХІТЕКТУРА і ПРОЦЕС.

## 1. Структура файлів — хто на кого спирається

```
catalog/*.js          ← чисті дані, БЕЗ логіки, нічого не імпортують
   (economy, resources, expeditions, locations, minigames, ...)
        ↓ require()
lib/mechanics/*.js     ← чисті ФУНКЦІЇ (можуть імпортувати catalog/ і одна одну)
   (heat.js, skills.js, storage.js, economy.js, levels.js, map.js, ...)
        ↓ require()
lib/user-store.js      ← модель гравця (createFreshUser/migrateUser/usersDB)
lib/auth.js            ← перевірка Telegram initData
        ↓ require()
routes/*.js            ← Express-роути, отримують усе через deps-об'єкт
   (map.js, economy.js — готові; social.js — написаний, НЕ підключений;
    misc.js, security.js — ще не існують)
        ↓ require() + виклик у server.js
server.js               ← оркестрація: підняти бота/сервер, роути, які ще
                           не винесені, і buildHtml() — весь клієнт
                           (HTML+CSS+JS) одним величезним template literal
```

**Правило залежностей: стрілка йде тільки вниз.** `catalog/` ніколи не
залежить від `lib/`, `lib/mechanics/` ніколи не залежить від `routes/`.
Якщо відчуваєш потребу зробити навпаки — знак, що дані/логіка не в тому
шарі.

## 2. Де саме міняти, залежно від того, що хочеш зробити

| Хочу... | Правити тут |
|---|---|
| Ціну/нагороду/шанс чогось наявного | `catalog/*.js` — просто число |
| Новий тип ресурсу/ящика/рецепта/локації | `catalog/*.js` — новий запис у масиві |
| Нову формулу розрахунку (не просто число) | `lib/mechanics/*.js` |
| Новий ендпоінт /api/... | `routes/*.js` (якщо домен вже винесений) або
  `server.js` (якщо ще ні — див. розділ 5) |
| Що показує/як виглядає гравцю | `server.js`, функція `buildHtml()` —
  шукай HTML-розмітку або відповідну `window.xxx = () => {...}` функцію |
| Стиль/колір/шрифт/форму кнопок | `server.js`, блок `<style>` на початку
  `buildHtml()` — CSS custom properties (`--bg`, `--accent`, `--gold` тощо) |

## 3. Порядок дій для БЕЗПЕЧНОЇ зміни (перевірено на собі багато разів)

1. **Прочитай** відповідний файл (`Read`), знайди точне місце.
2. **Зміни** (`Edit`, не переписуй файл повністю без потреби).
3. **`node -c server.js`** (і будь-який інший торкнутий `.js` файл) —
   синтаксис-чек, займає секунду, ловить 90% помилок одразу.
4. **Живий тест локально** (тільки БЕЗПЕЧНИЙ спосіб, інакше знімеш
   вебхук у живого бота):
   ```bash
   ALLOW_UNVERIFIED_DEV=true WEB_APP_URL=https://ukhylyant-simulator.onrender.com node server.js
   ```
   Потім `curl` до `http://localhost:3000/api/...` з `"id":"будь-який-номер"`
   у тілі запиту (dev-режим довіряє id з тіла, бо немає справжнього
   Telegram initData).
5. **Зупини сервер, видали `data/`** (тестові дані не мають потрапити
   в git — і так у `.gitignore`, але краще прибрати одразу).
6. **Коміт з описовим повідомленням** — що і чому, не що саме змінено
   рядок-у-рядок (це видно з diff).
7. **Пуш = автодеплой на Render.** Кожен пуш обнулює серверну пам'ять
   (безкоштовний тариф без диска) — **не пуш часто дрібними шматками**,
   групуй зміни. Якщо гравець зараз активно грає — попередь/почекай.

## 4. П'ять правил, які ламали речі раніше (не наступай на ті самі граблі)

1. **Ніколи не довіряй клієнту для чогось, що коштує грошей/ресурсів.**
   Кожна покупка/переїзд/крафт — сервер перевіряє й списує сам, клієнт
   лише показує результат. Виняток (клікер/`clickVal`) — свідомий,
   документований у CONTINUE_PROMPT.md.
2. **Новий прогрес гравця — одразу в 3 місця:** `createFreshUser`
   (lib/user-store.js), `RESTORE_*_FIELDS` (server.js, для `/api/restore`),
   і `saveToCloud()` (клієнтська функція в `buildHtml()`). Забув одне —
   поле губиться при редеплої. Це найчастіша дірка цієї сесії.
3. **`*_BY_ID` довідники — через `byId()` з null-прототипом** (lib/utils.js),
   не звичайний `{}`. Інакше `CATALOG['constructor']` падає в 500.
4. **Не клич важкі рендер-функції в гарячому 100мс-циклі** (`updateUI`).
   Важкі перебудови HTML — тільки в `init()` і після конкретної дії
   гравця (купівля/екіпірування), дивись `renderOwnedStuff()`.
5. **Гейти рівня — окремо для двох різних "рівнів"**: `user.level`
   (рівень схрону, 1-8, економічний, гейти на сервері) і
   `user.playerLevel` (XP-рівень ухилянта, лише UI-гейт клієнта,
   дим+замочок через `.locked`, нічого не ховається повністю).

## 6. Швидкий чек-лист "чому щось не працює"

- **Синтаксична помилка після Edit** → `node -c server.js`, читай рядок
  з помилки, зазвичай — необережний апостроф у кириличному рядку
  всередині одинарних лапок (`'don't'` ламає JS) — або цитуй через
  подвійні лапки, або екрануй.
- **Гравець втратив прогрес** → перевір, чи не ти щойно пушив (redeploy
  wipes memory на безкоштовному тарифі), і чи все нове поле є в усіх
  3 місцях з пункту 4.2.
- **Кирилиця прийшла як "???" у Telegram-повідомленні** → проблема
  кодування в shell/curl на Windows, не в коді. Пиши текст у файл
  (`Write`), відправляй через `curl --data-binary @file`, не через
  аргумент командного рядка.
- **Щось "працює на телефоні, але виглядає криво"** → перевір
  responsive на 320/360/414/768px, і чи не забув `font-family: inherit`
  на новому елементі (глобальний `button`-стиль це вже покриває,
  кастомні `<div>`-кнопки — ні).
