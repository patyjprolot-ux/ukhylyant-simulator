# Симулятор Ухилянта

Сатиричний Telegram Mini App клікер для друзів. Node.js + Express + Telegraf,
фронтенд (HTML/CSS/JS) віддається тим самим сервером із `server.js`.

## Локальний запуск

```bash
npm install
cp .env.example .env   # і встав свій BOT_TOKEN від @BotFather
npm start
```

Для локального тесту WebApp без реального https-домену зручно піднімати
тунель (ngrok, localtunnel) і прописувати його адресу в `WEB_APP_URL`.

## Деплой на Render.com (безкоштовний тариф)

Безкоштовний тариф Render існує тільки для типу **Web Service** — і сервер
тут якраз ним є (Express слухає HTTP-порт, `USE_WEBHOOK=true` за замовчуванням
означає, що Telegram сам стукає на сервер, а не сервер тримає з'єднання).
Через відсутність вхідного трафіку безкоштовний інстанс засинає приблизно
через 15 хв — перший вебхук-запит його розбудить, але з затримкою в кілька
секунд.

⚠️ **Важливо:** прогрес гравців (`usersDB`/`clansDB`) зберігається у файлі
`data/gamedata.json` поруч із сервером — кожні 20 сек і при коректному
зупиненні процесу. Це переживає засинання/пробудження безкоштовного
інстансу та звичайний рестарт (Render не видаляє диск між ними). Але диск
у безкоштовних інстансів **ефемерний і скидається при кожному новому
деплої** (`git push` → пересборка контейнера) — тож прогрес виживає
"сон", але не виживає оновлення коду. Якщо це стане проблемою — треба
зовнішню БД (напр. Postgres/Redis на Render) або платний тариф із
постійним диском.

### Кроки

1. Залийте проєкт у GitHub-репозиторій (без `.env` — він і так у `.gitignore`).
2. На [render.com](https://render.com): або **New → Blueprint** (підхопить
   `render.yaml` з цього репо автоматично), або **New → Web Service** вручну:
   - Runtime: Node
   - Build Command: `npm install`
   - Start Command: `node server.js`
   - Instance Type: **Free**
3. В Render → Environment задайте:
   - `BOT_TOKEN` — токен від @BotFather (реальне значення, не з `.env.example`)
   - `WEB_APP_URL` — публічний URL цього ж сервісу, вигляду
     `https://ваш-сервіс.onrender.com` (Render покаже його після першого
     деплою; якщо назва сервісу відрізняється від тієї, що в `render.yaml`,
     онови це значення й дай сервісу передеплоїтись)
   - `USE_WEBHOOK=true`, `ALLOW_UNVERIFIED_DEV=false` — так і лишити
   - `PORT` Render задає сам — не чіпати
4. Після деплою бот сам зареєструє вебхук на `WEB_APP_URL` при старті
   (див. `main()` у `server.js`) — окремих дій у BotFather не треба.
5. Щоб інстанс менше засинав, можна налаштувати безкоштовний пінг
   ([UptimeRobot](https://uptimerobot.com) або [cron-job.org](https://cron-job.org))
   на `https://ваш-сервіс.onrender.com` кожні ~10 хв. Це не гарантує 24/7 —
   для стабільної роботи знадобиться платний тариф.
